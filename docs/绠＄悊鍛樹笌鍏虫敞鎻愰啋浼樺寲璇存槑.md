# 管理员与关注提醒优化说明

## 真实身份编号

旧版本在 `USE_CLOUD: false` 时使用 `local-user-openid`，该值只能用于本地演示，不能配置真实管理员。V4 默认开启云开发，并通过 `cloud.getWXContext().OPENID` 返回用户真实身份编号。

如“我的”页面仍未显示真实 OpenID，请依次检查：

1. 使用真实小程序 AppID。
2. 已绑定云开发环境。
3. 已创建七个数据库集合。
4. 已重新部署 `cloudfunctions/api`。
5. `config.js` 的 `USE_CLOUD` 为 `true`。

## 超级管理员初始化

应用启动后会调用 `me` 接口完成身份初始化：

- `admins` 为空：当前第一个用户自动写入为 `super_admin`。
- 已有旧管理员但没有 `super_admin`：优先升级当前已存在的管理员；否则升级创建时间最早的管理员。
- 已存在超级管理员：不再自动改变角色。

超级管理员可在管理面板添加或移除普通运营管理员。超级管理员不能在面板中删除自己，也不能删除另一个超级管理员。

## 关注模型升级

旧版收藏以 `stallId` 为单位，同一摊主发布新场次后需要重新关注。V4 改为以 `vendorOpenid` 为单位：

- 用户在任意场次点击关注，即关注该摊主。
- 摊主之后发布新场次，列表、地图和详情会继续显示已关注。
- 关注页为每位摊主选择“正在出摊、下一场、最近一场”中的最佳记录。
- 旧版收藏记录会自动迁移，不需要手工清库。

## 到时提醒

### 小程序内提醒

`app.js` 在以下时机调用 `favoriteDueAlerts`：

- 小程序打开或回到前台约 1 秒后。
- 小程序保持前台期间每 60 秒一次。

当关注摊主的场次满足 `startAt <= 当前时间 <= endAt` 时显示弹框。同一场次的已提醒状态保存在本机 48 小时，避免反复弹出。

### 微信系统消息

用户点击关注时立即请求一次性订阅授权。授权成功后：

- 已有下一场出摊：订阅记录状态为 `pending`，发送时间为场次开始时间。
- 暂无下一场：状态为 `waiting`；摊主发布新场次时自动改为 `pending`。
- 取消关注：尚未发送的 `waiting`、`pending` 记录改为 `cancelled`。
- reminder 云函数每分钟检查一次，只在到达发送时间后发送，不提前推送。

微信限制小程序在关闭状态下直接弹出界面，因此关闭小程序后的提醒必须依赖用户主动授权的一次性订阅消息。小程序内弹框用于前台或再次打开时提醒。
