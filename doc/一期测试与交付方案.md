# 一期测试与交付方案

> 开发前准备资料第 6 项／共 6 项。状态：待审稿，尚未执行测试、迁移、灰度或交付。本稿规定一期 MVP 的验证方法、证据、缺陷处理、发布演练和试点评审；实际环境、人员、日期、测试结果与签收记录须在实施后填写，不能以本计划代替通过证明。

## 1. 依据、目标与边界

[一期 MVP 需求文档](MVP/一期MVP需求文档.md)是业务与 AC-01～AC-20、R-01～R-08 的验收依据；[页面与交互方案](一期页面与交互方案.md)定义 P01～P18 的页面与异常状态；[技术设计](一期技术设计.md)定义权威时间、公开资格与故障处理；[数据模型与接口约定](一期数据模型与接口约定.md)定义表、HTTP、错误、幂等和保留；[实施计划](一期实施计划.md)的 G-01～G-06 与 W1～W12 是测试进入条件和阶段顺序。

验收对象是可运行的一期系统：微信小程序、可信身份入口、Express API、MySQL 迁移与权威状态、受控作业、管理操作、公开与受限数据边界。离线原型、静态语法通过或单独 API 成功均不能替代端到端验收。日历、预约、关注、最近位置公开、信用、完整授权工作台及永久注销不在一期验收范围；测试仍须确认一期页面与接口没有暗示或意外开放这些能力。

本方案的“通过”表示在指定版本和环境有可复核证据；部署到另一环境后须复核身份、数据库、路由、调度和关键安全场景。真实云资源、试点范围、名单、负责人、发布日期和数据库版本目前未确认，相关表格保持待填，不能预设已具备。

数据准备在隔离环境使用合成账号和测试坐标；真机现场测试只在约定测试点进行，普通证据不保存顾客精确坐标、openid、令牌或管理证据全文。至少准备匿名顾客、普通账号、首次申请者、已审核摊主 A／B、资料修改待审者、`PROFILE_REVIEWER`、`FIELD_REVIEWER`、`ADMIN`、`SUPER_ADMIN`、无权管理旧账号和作业身份。摊主 A 的数据含 `S1/L1→L2`、同日新轮 `S2`、跨零点轮次、双重限制与清除请求；反馈数据含同人同日同类不同轮次事实、不同顾客相同类型、已结案事项及未结保留事项。每例重置到明确状态或使用独立 ID，避免上一例改变后续判断。

开始正式验收前，需在记录中锁定：代码提交与小程序构建号、契约版本、迁移校验和、目标 MySQL 版本、网关与管理授权配置、作业身份与调度、试点与性能样本范围。第 5 项 G-01 的公告、字段长度、品类码未确认时，相关表单边界只能标“待定／阻塞”，不能按建议值判通过；G-02～G-05 无实际证据时，目标环境的对应项目也只能标“未测”。

## 3. AC-01～AC-20 端到端验收矩阵

每行均需分别检查界面表现、权威 API 结果和必要的数据库／审计事实；“不应出现”须以响应字段缺失、记录数量或状态未改变证明。自动化覆盖稳定的状态和边界，真机与现场部分另留人工记录。

| 场景 | 前置与操作 | 必须核对的结果 | 证据重点 |
| --- | --- | --- | --- |
| AC-01 | 顾客拒绝定位，打开 P01 列表与地图并切品类 | 仍见完整当前公开集合；无本人点和个人距离；地图与列表同源 | 两视图对象 ID 集合、公开响应无顾客坐标、拒绝授权录屏 |
| AC-02 | 首次资料提交后待审，再驳回；顾客查询且本人尝试开摊 | 待审／驳回都不公开、不开摊；本人看到状态和原因 | 资料版本／生效指针、开摊拒绝码、P07／P09 |
| AC-03 | 已审核摊主确认有效截止并成功定位开摊 | 只成一轮、一个初始位置和当日记录；列表／地图／详情显示本轮位置与截止 | 同键回放前后行数、轮次／位置 ID、公开投影 |
| AC-04 | 截止无效、定位拒绝／失败、定位后时间失效或取消 | 仍休息；不生成轮次、位置或出摊日；本人见可重试原因 | 开摊尝试终态与业务表差异、P09 提示 |
| AC-05 | 本轮从 L1 成功刷新到 L2，随后刷新失败 | L2 是唯一当前导航位置；失败保留 L2 和真实定位时间，不加出摊日 | L1 停止时刻、L2 生效、导航复核、日记录 |
| AC-06 | 到准备收摊阈值，顾客在 P02 点击导航并选择继续 | 先显示截止和剩余时间；确认后再在线复核才发起导航 | 阶段计算、弹层与两次复核顺序 |
| AC-07 | 顾客保留旧详情，摊主手动收摊后顾客点击导航 | 新读取为休息；导航复核拒绝且无旧坐标 | 结束及位置停止审计、网络响应字段、真机操作 |
| AC-08 | 小程序关闭，到截止；到期作业延迟、重复和并发运行 | 截止等号新读取／导航立即失效；作业最终只写一次结束且结束时刻为截止；前台页按 R-01 同步 | 主库时刻、作业多次执行记录、页面同步时间 |
| AC-09 | 同日两次成功开摊；另一轮跨零点持续后次日再开 | 同日仅一个出摊日；跨零点不自动加次日，次日主动新开才加 | 开摊日唯一键、P10 天数及记录 |
| AC-10 | 有效窗口内、符合定位条件提交反馈；同人重复同类提交，另一顾客提交同类反馈 | 本人有待处理记录、管理有待审事项；同人重复事实不增数，不同顾客各有事项而管理列表可聚合；无自动处罚／收摊 | 原操作回放、按提交人区分的事实／事项数量、营业状态 |
| AC-11 | 管理暂停正在营业的摊主，与旧开摊请求竞争；随后解除 | 暂停立即结束本轮并隐藏资料／坐标；旧请求不能恢复；解除后仍休息 | 版本竞争、双控制列、顾客各入口和审计 |
| AC-12 | 生效资料 V1 下提交 V2，审核期间及驳回后顾客重读 | V1 持续公开，V2 不生效；本人见驳回原因 | 生效指针与公开字段、审核记录 |
| AC-13 | 无权账号从旧管理页面或直接 HTTP 请求审核／暂停 | 拒绝且无资料、轮次、限制或审计成功事件变化；撤权后已开页面同样拒绝 | 可信与直连两条路径、权限快照、前后状态 |
| AC-14 | 本轮长时间不刷新，再主动刷新失败，随后到期 | 营业中保留最后成功位置和真实时间、不虚构后台跟踪；到期立即停止新读取和导航 | P09／P02 时间文案、位置版本、截止边界 |
| AC-15 | 反馈位置距离原位置恰 300 米／略超；新鲜度恰 5 分钟／略超 | 恰好上限在其他条件满足时受理；超过任一项拒绝且不插事实 | 未取整距离、主库受理时刻、事实行数、字段错误 |
| AC-16 | `S1/L1→L2` 或同日重开 `S2`，用旧观察反馈；管理跨轮次合并核实 | 每条事实仍引用原 `S/L` 并逐条记结果；顾客无旧坐标；历史结论不自动关闭 S2，当前纠错须另指定 S2 与依据 | 原引用、`factResults` 覆盖、管理历史／当前分区与审计 |
| AC-17 | 离开详情后从 P04 找回观察；结束后 30 分钟前后、跨零点提交 | 窗口内可提交；等号关闭候选与新提交；同类待审按事件当地日合并，已提交仍可查 | 观察事件日、候选列表、事项唯一键、本人记录 |
| AC-18 | 顾客旧详情或地图断网／权威读取失败，再点击导航，随后恢复网络 | 标“未更新”，不以缓存坐标新导航；恢复后先复核并按最新状态决定 | 断网录屏、导航调用次数、恢复复核响应 |
| AC-19 | 本人营业中停止公开、请求清除；同时有治理暂停，再尝试恢复 | 立即结束轮次并隐藏；清除有状态／期限／保留说明；本人恢复不解除治理，资料已清除需重新审核且不恢复旧轮／位置 | 停止与清除两份记录、双版本、公开投影、P11～P13 |
| AC-20 | 成功替换位置、收摊或暂停；到各版本保留截止且分别有／无未结事项 | 旧坐标不再公开；各位置从自身停止时刻起算，未结或延期按较晚截止，届期删除或去标识化 | 旧路由扫描、逐版本截止与清理审计、受限复核权限 |

AC-16 的跨轮次合并不能只检查事项最终状态：必须为每个事实记录原轮次、原位置、核实结果和原因；若结案同时出现新增事实，旧 `taskVersion` 决定应冲突而不能遗漏事实。AC-07／11／18／20 的坐标检查覆盖新公开接口、旧公开路由、错误体、客户端缓存与导航最后复核。AC-15 的边界用可控主库时刻和确定的测试坐标计算，不能以手动移动手机“约 300 米”替代精确边界测试。

管理复核还须用两份未确认事实分别验证 `INSUFFICIENT_EVIDENCE`（证据不足）和 `DISPROVED`（已证明不存在异常）的原因及本人可见说明；事项结案后不能被迟到事实重新打开。反馈人坐标和身份只可在有权受限复核中读取。

## 4. R-01～R-08 质量、权限与隐私验证

| 要求 | 方法与判定 | 留存证据 |
| --- | --- | --- |
| R-01 权威状态与同步 | 让开摊／收摊／刷新／暂停等状态在主库成立；立即向新读取和新导航发请求，应读到新权威结果。前台已打开 P01／P02／P09 在正常网络下从成立到显示同步不超过 60 秒；`onShow`／网络恢复先复核，失败时标未知并禁止缓存导航 | 服务端成立时间、客户端收到时间、网关日志的 `requestId`、录屏和失败注入结果 |
| R-02 时效 | 在记录的代表性设备、正常网络、预期公开集合与并发量下分别测首页／详情主要内容可用、开摊／收摊明确结果、成功刷新位置后另一顾客的地图／详情／导航可用；每项计算原始样本的第 95 百分位并对照 2.5／3／5 秒 | 每次起止时刻、样本量与剔除理由、原始分布、p95、设备／网络／负载、慢请求追踪 |
| R-03 幂等并发 | 同键同体重放、同键异体、不同键竞态、超时后原键查询；审核、开摊、刷新、收摊、两类限制、清除和管理决定与作业并发 | 操作键摘要、版本变化、成功结果 ID、唯一行数与审计数 |
| R-04 最少信息 | 匿名浏览无需手机号／头像；逐接口扫描顾客、本人、管理不同角色的响应、URL、普通日志、缓存和本地持久化 | 字段白名单对照、无权响应、脱敏日志检查和真机存储检查 |
| R-05 审计 | 审核、反馈决定、治理、本人选择、清除、营业开始／结束及每次位置生效／替换／停止均有时间、结果和必要操作者／原因；强制审计写失败时业务不成立 | 业务事实与审计一一对照、故障注入结果、读取审计 |
| R-06 业务边界 | 页面文案、路由与客户端包装扫描，确认未开放预约、支付、库存、信用、日历、最近位置公开等后期能力 | P01～P18 页面审阅记录、API 路由清单和旧入口访问结果 |
| R-07 保留与清除 | 各位置自身停止后 180 自然日、一般证据事项结案后 180 日、管理与高风险治理审计发生后 1095 日及本人 30 日清除；未结事项、结案后 30 日和有依据延期按较晚时刻处理，重试不重复清理或回显 | 可控时钟边界、清理前后脱敏状态、保留依据与到期、本人查询结果 |
| R-08 上海时间 | 数据库会话 UTC、API 毫秒整数、本地日 `[00:00,次日 00:00)`；营业截止和反馈 30 分钟窗口等号不含，跨零点去重与自然日加法正确 | 主库时刻、时区配置、边界用例断言和日期记录 |

R-02 的正式测量须在 G-05 确定“正常网络”和预期容量后执行。开摊测量的主指标从用户确认并完成本次定位、发起最终开摊提交起到获得明确结果；同时另记从点击到定位返回的用户全程耗时，不能用后者的剔除掩盖定位体验。收摊从点击确认到明确结果。刷新位置传播从权威事务提交到另一顾客端新读取、地图／详情展示及导航复核均得到新版本，按最慢的必要链路判定。首页／详情从进入页面到主要内容可操作。失败、超时和被排除样本须分类列出，不得只统计成功的快请求；样本量、网络档位和负载与业务负责人在测量前锁定，不在结果出来后调整口径。

安全与故障注入还应覆盖：伪造可信身份头、直连服务、撤销角色后旧页面继续操作、越权读取其他账号、管理详情受限证据、作业接口经小程序网关访问、旧公开路由与缓存回退、主库不可用、事务审计失败、作业中途失败、死锁后同键有限重试。发现公开旧坐标、顾客位置进入普通日志、清除后重新公开或无权管理成功，均属于发布阻断。

## 5. 测试记录、缺陷与复测

每个 AC／R、页面状态或演练动作使用统一记录：编号、依据条款、代码提交／小程序构建／数据库迁移版本、环境与设备、前置数据 ID、操作步骤、预期与实际、`requestId`／原操作键摘要、证据链接、执行时间、执行人、结论（通过／失败／阻塞／未测）、关联缺陷。证据只保留必要摘要；受限坐标、身份和审核材料在有权系统留存，普通测试报告只写受限证据编号。自动化结果与人工录屏均须可关联同一版本，旧版本通过记录不能转记为新版本通过。

| 缺陷级别 | 示例 | 处理门槛 |
| --- | --- | --- |
| 阻断 | 旧坐标公开、无权管理成功、清除后重新公开、双活营业、错关新轮、迁移丢失事实或回退泄露 | 停止切换或灰度；修复后重跑相关 AC／R、权限与回退检查 |
| 高 | AC 不通过、R-01／R-02 指标不达标、反馈漏事实、到期作业无恢复、资料保留期限错误 | 不进入发布签收；修复并复测相关链路和邻接场景 |
| 一般 | 不影响权威事实和隐私的页面提示、布局或非关键操作问题 | 记录影响和处理时点；若涉及 AC 页面结果仍须修复后通过 |

每次修复至少复测失败例、同一领域相邻边界和受影响页面；数据或公开资格变化再复测旧路由、导航、审计与清理。不能以“已修复”或代码审阅代替新版本执行结果。对尚无真实环境的项明确标阻塞或未测，保留责任人和解除条件。

## 6. 迁移、作业、灰度与回退演练

1. **发布前清点。** 记录目标数据库备份与恢复点、迁移状态及校验和、旧 `cb_vendor_locations` 数据量和消费者、旧公开路由清单、管理及作业身份、网关转发、容器脚本和监控告警。旧位置是否有受限保留依据逐类记录，不直接删表或把 `RECENT_LAST` 归入新轮次。
2. **隔离环境演练。** 分别从空库和现有迁移快照执行向前迁移、重复执行、失败中断与恢复；验证活动唯一约束、孤儿检查和受限归档。对新旧读做对账，只用于发现差异，旧记录不成为一期公开权威。
3. **功能与安全切换。** 新后端先在受控范围验证；旧公开坐标路由必须关闭顾客访问或改走统一投影，再允许新小程序灰度。扫描未升级客户端、旧深链和直接 HTTP 请求；任何一条仍可取得停止公开的位置则停止切换。
4. **作业演练。** 到期、清除、保留期清理及每日完整性检查分别跑正常、重复、部分失败与断点恢复；验证作业身份只在内部可用、迟到任务不操作新轮次、清除失败有重试和本人可见进度。记录每批成功／跳过／失败数、游标、异常报告和告警触发。
5. **灰度观察。** 预先确定参与范围和时间窗；持续看公开查询错误、导航复核拒绝、超时、双活／孤儿异常、作业积压、清除超期、旧路由命中及关键性能。灰度扩量须回看 AC/R 抽样与现场核验，不以无投诉推定准确。
6. **回退演练。** 预演停止新写、撤回新客户端或新接口、恢复兼容应用的顺序；逐步证明不会因旧代码重新公开历史坐标、清除资料或已结束轮次。已提交的新事实和审计保留，不能靠删除新表“回滚”。若无法证明安全回退，维持失败关闭并修复前向问题。

生产迁移、灰度和回退都需单独发布批准与当次操作记录。本稿只是演练步骤，不代表授权触碰真实数据库或上线。已经发起的外部微信导航无法保证撤回；验收重点是平台不能再提供新的旧坐标导航。
