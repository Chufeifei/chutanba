# 出摊吧｜第一期实时找摊 MVP 需求文档

> 状态：待业务评审。本文定义第一期要交付和验收的业务结果，不表示已经开发完成，也不规定接口、数据库或页面代码结构。
>
> 第一期直接开发与验收的唯一业务需求依据是本文。分期开发规划只说明后续开发顺序；已归档的完整需求可用于核对原始业务意图，但不直接扩大第一期范围。若核对发现本文遗漏了第一期必需规则，须先修订本文再开发和验收。未列入第一期的能力是后置，不是取消。

## 1. 本期目标与边界

**要验证的问题：** 顾客能否通过小程序找到此刻真实出摊的本地摊主，并依据最新位置导航；摊主能否愿意持续使用主动开摊和收摊。

**最短闭环：** 摊主提交基本资料 → 人工审核通过 → 摊主确认预计收摊时间并实时定位开摊 → 顾客在列表或地图发现摊主、查看详情并导航 → 摊主手动收摊或平台到时自动收摊 → 顾客不再看到旧的营业位置。

本期面向有一定摊主供给的试点片区。试点开始前明确片区、参与摊主与人工审核和纠错负责人；第一期的“本地”以该试点范围为业务前提，不增加跨区域或半径筛选。没有正在出摊的摊主时展示明确空状态；不使用虚构摊位、旧定位或预计地址填充地图。

### 1.1 本期交付

| 角色 | 必须交付的能力 |
| --- | --- |
| 顾客 | 浏览当前出摊摊主的列表和地图、按品类查找、查看详情与状态、导航、提交简易现场状态反馈并查询处理结果 |
| 摊主 | 提交和修改基本资料、查看人工审核结果、定位开摊、营业中刷新位置、手动或到时自动收摊、查看当前状态和基本出摊记录、主动停止或恢复本人公开及清除不再需要的个人资料 |
| 管理人员 | 人工审核资料、复核现场状态反馈、纠正错误营业信息、实施或解除治理暂停公开、处理必要的资料争议、记录处理原因与操作人 |

### 1.2 本期明确后置

- 预计出摊日历、预计出摊时间、计划日履行、请假及“请假中”状态。
- 关注、“今天想去”、预约记录和二维码、核销、预约福利、微信订阅提醒。
- 最近出摊位置公开、收摊后地图标记、跨区域或半径筛选。
- 完整商品列表和显隐排序、摊位头像与内容图片、人均价格区间等丰富资料。
- 信用分、经营标签、信用申诉、内容举报、限制出摊、摊主永久注销。
- 推广二维码和贴纸、AI 资料审核、人员授权工作台及精细运营规则。

本期公开业务状态仅为**出摊中、休息中**；“准备收摊”只是出摊中的展示阶段，“治理暂停公开”是管理限制，“本人停止公开”是摊主自主选择，后两者都不是新增公开状态，也不相互解除。由于尚无计划日，本期不对顾客作未来出摊承诺，也不产生未按计划出摊事件。

## 2. 角色与入口

- **顾客：** 可浏览公开内容，无需授权微信头像、昵称或手机号；拒绝顾客定位后仍能浏览列表和地图上的公开摊位，但不计算个人距离。提交现场反馈时需要可识别的当前平台账号和本次位置授权，不要求手机号。“我的 → 现场反馈”提供仍在受理窗口内的待反馈入口、已提交记录及处理结果。
- **摊主：** 同一个平台账号可以浏览顾客内容并申请摊主身份。审核通过后，在“我的”切换到摊主工作台。每名摊主只有一份当前生效的公开资料。
- **管理人员：** 第一期只开放完成审核、现场纠错、治理暂停及必要资料争议处理所需的受控管理入口。最高权限账号由部署时受控配置，不通过首次访问或客户端参数自动获得；管理入口和每次管理操作均重新校验权限。完整人员授权与运营员分工在第三期提供。

## 3. 顾客需求

### C-01 发现当前出摊摊主

1. 首页列表和地图只展示**已审核、未被治理暂停、本人未停止公开、权威状态为出摊中且有有效营业定位**的摊主；可按品类查找。有效营业定位按 V-03 判定；“出摊中”来自摊主主动开摊及本轮截止规则，现场是否相符仍须通过试点核验和人工反馈复核验证。第一期不提供未来计划或“附近常驻摊位”标记。
2. 顾客允许定位时，可显示到公开营业位置的距离，并在同一品类内优先显示较近的摊主；拒绝定位时仍显示全部当前公开摊位，使用稳定顺序，不暴露任何内部信用排名。
3. 列表、地图和详情使用同一权威状态。摊主收摊、到时自动收摊、本人停止公开或被治理暂停后，新的读取立即按新状态和公开资格返回；已打开页面按 R-01 同步，不得在同步后继续把旧缓存标成正在出摊。
4. 无当前出摊摊主、定位不可用或加载失败时分别给出可理解的空状态或重试入口，不虚构摊位和距离。

### C-02 查看详情与导航

1. 详情展示当前审核通过的摊位名称、品类、常卖内容、价格说明、公告、出摊状态、当前导航位置的更新时间和本轮预计收摊时间；价格只作参考，不承诺实际成交价格。
2. 从旧链接打开已收摊摊主的详情时，可显示“休息中”和仍允许公开的基本资料，但不显示旧营业坐标、个人距离或导航入口。本人停止公开或被治理暂停时只显示不可查看结果，不泄露资料和位置。
3. 顾客点击导航前，平台再次检查摊主当前状态、是否已到预计收摊时间以及当前位置是否仍可公开。已收摊或位置失效时不返回旧坐标；仍在准备收摊时明确提示预计收摊时刻与剩余时间，由顾客选择继续或暂不前往。
4. 详情明确说明平台只提供找摊信息和导航，不保证摊主持续营业、商品有货或线下交易结果。
5. 本文的导航验收范围是小程序内每次新发起导航前的复核，不承诺撤回顾客此前已经获得的信息或中止已经发起的外部导航。再次从小程序发起导航仍须重新校验；无法确认最新状态时不得使用旧坐标继续发起。

### C-03 简易现场状态反馈

1. 顾客可就事件发生时显示“出摊中”的摊主选择“老板不在”“地点不符”或“已经离开”，并补充简短说明。第一期不上传现场照片，不开放一般内容举报。
2. 反馈可在对应轮次仍出摊时或其实际结束后不足 **30 分钟**时提交，达到结束后 30 分钟即关闭该轮新反馈。顾客可从摊主详情进入；详情曾展示的营业轮次或曾发起导航的轮次，在受理窗口内可从“我的 → 现场反馈”找回待反馈入口。该入口只保留本人定位反馈对象所需的最小上下文，不作为公开浏览历史；窗口结束后移除未提交入口，已提交反馈按 R-07 保留。
3. 提交时取得顾客本次位置，定位时间距提交不得超过 **5 分钟**，且与事件发生时有效的营业位置距离不超过 **300 米**。定位失败、拒绝授权、位置过期或超出范围时说明无法完成现场核验并允许重新定位，不受理为有效现场反馈，不影响普通浏览和导航。该能力要求提交时仍可完成现场附近核验，不承诺顾客离场后凭历史位置补报。
4. 每条反馈事实注明异常发生时间，并对应具体营业轮次、当时的公开状态和当时生效的位置版本；事件时间必须落在该轮曾公开出摊的时段内，不能用顾客任意填写的时间代替平台记录。位置刷新、收摊或同日重新开摊不得把反馈对象替换为新位置或新轮次；必要历史只供受限核验，不经反馈入口向顾客返回旧坐标。本人停止公开或被治理暂停时不恢复公开资料，已取得的本人反馈入口和记录只显示必要事件摘要与处理状态。
5. 同一顾客对同一摊主、同一自然日、同一问题最多保留一条待处理反馈，自然日以异常发生日为准。同类新事实补充到已有待处理反馈，并分别保留发生时间与对应轮次；相同事实重复提交不重复生成。同一事实不得因合并、重复提交或多次复核而重复处理或处罚。
6. 反馈提交成功后可在本人记录中查看“待处理、已核实、未核实”及必要说明；无法核实与已证明不存在异常应在说明中区分，不向顾客公开内部证据和管理备注。
7. 反馈只形成待复核线索，不自动收摊、暂停公开、扣分或向顾客公开摊主内部处理信息；管理人员复核后才能采取纠正措施。

## 4. 摊主需求

### V-01 基本资料与审核

1. 摊主从统一入口提交名称、品类、至少一项常卖内容或商品说明、价格说明和公告。第一期不填写固定出摊地址，也不要求预计出摊日历或时间；不上传摊位图片，顾客端使用平台默认品类视觉。
2. 首次资料必须人工审核。审核中、通过或驳回的状态与原因对摊主可见；未通过前不能出现在顾客端，也不能开摊。
3. 已审核摊主从同一入口修改资料，修改内容经人工审核后才成为新生效版本；审核期间原已通过版本继续公开，驳回不覆盖原版本。长期内容不设“当次出摊编辑”。

### V-02 主动一键出摊

1. 仅已审核、未被治理暂停、本人未停止公开、具有当前生效基本资料且处于休息中的摊主可以开摊。预计出摊时间不是本期资料字段；每次开摊必须单独确认**本轮预计收摊时间**。
2. 从未有有效上次选择时，默认推荐平台当前时间后 4 小时并向上取整到最近 30 分钟；上次成功选择的钟点按本次“今天／次日”换算，仍满足本次时间约束时可作为默认候选，但须重新确认，不复用已经过去的日期。选择器明确显示“今天／次日”和完整时间。
3. 本轮预计收摊时间必须晚于平台当前时间，且从实际定位开摊到截止时刻不超过 12 小时。所选时刻与当前时刻相同不能提交；早于当前时刻的钟点按次日理解。定位完成时再次校验时间。
4. 摊主确认时间后，平台获取本次实时定位。**只有定位成功**，才以同一个业务结果记录实际开始时间、截止时间、当前导航地址和“出摊中”。定位失败、取消或结束时间失效时保持休息中，并说明原因、允许重试。
5. 非首次当天开摊仍须重新选择有效结束时间并重新定位；同一自然日重复开摊只形成一个出摊日，不重复累计天数。网络重试或连续点击不产生第二轮相同营业结果。

### V-03 出摊中工作台与位置

1. 工作台展示“正常营业／准备收摊”、本轮预计收摊时间、剩余时间、当前导航位置和最后定位时间，并提供“刷新位置”“收摊”。第一期不提供延长营业。
2. 以实际开始时间 `S`、结束时间 `E`、平台当前时间 `N` 计算剩余时间 `R=E-N`，准备收摊阈值 `T=min((E-S)×25%, 60 分钟)`。`R>T` 为正常营业；`0<R≤T` 为准备收摊；`R≤0` 按到时收摊处理。准备收摊仍属于出摊中。
3. 营业中只有摊主主动点击刷新位置且定位成功，才更新唯一的当前导航地址；顾客列表、地图、详情和导航使用最新成功位置。刷新失败保留上次成功位置并提示失败，不重复形成出摊日。
4. 平台不在后台持续获取摊主位置，不使用注册资料、历史定位或顾客位置代替本轮营业定位。
5. **有效营业定位**指摊主在本轮主动开摊或主动刷新时成功取得、具有可用于地图与导航的有效坐标、且未被后续成功定位替换的本次定位结果；无有效坐标或不能形成可导航位置时按定位失败处理。其公开有效期止于本轮手动、自动、本人停止公开或管理结束时刻，不另设定时打卡、定位超时自动收摊或未定义的定位精度数值门槛。
6. 本轮内未刷新或刷新失败，不单独使上次成功位置失效；顾客端持续展示最后成功定位时间，不把它解释为后台实时跟踪结果。摊主移动营业地点后应主动刷新，停止营业应收摊。每次成功位置的生效、替换和停止公开时间均须可追溯，以支持对事件发生时位置的受限核验。

### V-04 手动与自动收摊

1. 摊主可随时手动收摊；到达本轮预计收摊时间，平台即使在摊主未打开小程序时也必须自动收摊。即使后台任务延迟，读取状态或发起导航时也必须先按平台时间判定本轮已经到期。实际结束时间分别取手动收摊、本人停止公开或治理结束的成立时间，或到时自动收摊的本轮有效截止时间。
2. 收摊后回到休息中，当前导航地址立即停止以营业位置名义公开；第一期不公开最近出摊位置。旧列表、地图、详情和导航在重新读取时不能获得旧营业坐标。
3. 工作台可查看累计出摊天数和基本出摊日记录。同一自然日多次开摊只累计一天；连续营业跨越零点不自动增加次日出摊日，次日收摊后再次主动定位开摊才形成次日记录。
4. 手动与自动收摊并发、自动任务重试或重复点击只能形成一次本轮结束结果；已结束的本轮不能被旧请求重新置为出摊中。

## 5. 最小管理需求

### O-01 资料人工审核

- 管理人员查看注册或修改申请、必要资料与历史审核结果，作出通过或驳回并记录原因、处理人和平台时间。首次审核通过后才授予摊主公开及开摊资格。
- 一次修改待审核期间，原已通过资料持续生效。被驳回版本不能因重试或页面缓存而公开。

### O-02 现场纠错与暂停公开

- 管理人员查看简易现场反馈、异常发生时的营业轮次、状态和位置版本，以及提交时状态，标记核实结果，并在必要时结束错误营业或暂停资料公开；每次处理记录证据摘要、原因、操作人和时间。核实历史轮次的异常不自动结束后续新轮次；结束当前轮次须另核实当前异常并记录依据，暂停公开则按治理规则执行。
- 只有管理员或最高权限管理员可以实施或解除**治理暂停公开**。治理暂停立即结束正在营业的本轮、隐藏公开资料和位置；暂停期间禁止开摊。解除后保持休息中，不恢复旧营业或旧坐标，摊主须重新定位主动开摊；解除治理暂停不能清除仍然有效的本人停止公开选择。
- 摊主能查看对本人产生影响的处理原因和结果，并申请人工复核。第一期以最小记录和人工处理实现，完整信用申诉与人员分工在第三期建设。

### O-03 本人停止公开与个人资料处理

- 已审核摊主可从“我的”的摊主资料与处理记录主动选择“停止公开”。重新确认本人账号和影响后，操作成立即结束正在营业的本轮、停止公开基本资料与全部营业位置，公开业务状态回到休息中，禁止再次开摊；不等待管理员受理，不标记为违规或失信，也不使用治理暂停公开的权限。页面持续显示“本人已停止公开”及操作时间。
- 本人可以主动恢复公开；恢复仅解除本人的停止公开选择，不解除独立存在的治理暂停。若已清除开摊所需的基本资料，须先重新补齐并通过人工审核，不恢复已删除内容；恢复后保持休息中，不自动开摊或恢复旧位置。本人的停止与恢复操作均记录本人账号和成立时间，重复点击或旧请求不得撤销较新的本人选择或治理结果。
- 本人可从同一入口请求清除不再需要的个人资料并查询进度和结果。确认本人账号和可清除范围后直接进入处理，不以管理员受理作为前提；可清除的非必要完整值自请求成立时起 30 个自然日内清除，无法清除的必要受限记录按 R-07 说明保留依据与期限。清除范围包含当前生效的摊主公开资料时，先立即按本人停止公开处理，待审核修改也不得在清除后自动恢复公开；处理争议时才进入人工核查。停止公开与资料清除分别记录，隐藏页面不等于资料已经删除。
- 第一期不执行不可恢复的摊主身份永久注销，完整永久注销流程仍在第三期交付；自助停止公开不等于永久注销。

| 编号 | 第一期开发表现与验收要求 |
| --- | --- |
| R-01 权威状态 | 业务操作和平台截止时间立即改变权威结果，新的读取与新发起的开摊、导航或管理操作均须立即按最新权威状态判断。正常网络下，已打开且处于前台的列表、地图、详情和工作台最多 60 秒同步；恢复前台先复核。断网或同步失败时明确提示状态未更新，不承诺仍在营业，不得以缓存坐标新发起导航；重新取得最新结果后再恢复相关操作。 |
| R-02 时效 | 正常网络下首页与详情主要内容 95% 在 2.5 秒内可用；开摊或收摊 95% 在 3 秒内返回明确结果；成功刷新位置后 95% 在 5 秒内用于顾客端地图、详情和导航。 |
| R-03 幂等与并发 | 重复审核提交、开摊、收摊、定位刷新、本人停止或恢复公开及治理暂停不应产生重复记录或互相覆盖错误状态；本人停止公开或治理暂停生效后，旧开摊请求不得恢复公开。本人恢复公开不得解除治理暂停。 |
| R-04 最少信息 | 顾客浏览和导航无需授权手机号；摊主营业位置仅在出摊中对顾客公开；顾客反馈位置与身份仅供有权限管理人员复核，不进入摊主公开资料。 |
| R-05 审计 | 人工审核、现场反馈处理、治理暂停与解除、本人停止或恢复公开、本人资料处理、营业开始与结束，以及每次营业位置的生效、替换和停止公开，均保留可追溯的时间、结果和必要操作人或原因；不向顾客公开位置历史和管理证据。 |
| R-06 业务边界 | 本期不产生预约、支付、订单、库存、未来出摊承诺或统一消息中心；所有页面和提示均不得暗示这些能力已经提供。 |
| R-07 数据保留 | 一般审核与反馈证据在事项结束后默认保留 180 个自然日，之后删除或去标识化；管理与高风险治理审计从事件发生后默认保留 1095 个自然日。每一营业精确位置版本从被替换、收摊、本人停止公开或治理暂停等停止公开时刻起，默认受限保留 180 个自然日，之后删除坐标或去标识化；关联反馈、申诉或安全事项未结束时保留至事项结束后 30 个自然日，以两者较晚者为准。停止公开的位置只能供有权限的复核与审计使用，不得经顾客页面或公开接口返回；一般管理审计期限不自动延长精确坐标期限。争议延期须记录依据与新截止时间。 |
| R-08 时间口径 | 平台业务时区固定为 Asia/Shanghai（UTC+8）；自然日为当地时间 `[当日 00:00, 次日 00:00)`。营业与反馈受理窗口均不含截止时刻；到达本轮截止时刻即按已收摊处理，到达结束后 30 分钟即不再受理该轮新反馈。除按自然日去重的统计外，“自某时刻起 N 个自然日”按 `[起始时刻, 第 N 日相同本地时刻)` 计算，覆盖本人的资料处理和数据保留期限。 |

## 7. 端到端验收场景

| 编号 | 操作 | 必须看到的结果 |
| --- | --- | --- |
| AC-01 | 顾客拒绝定位后打开首页和地图 | 仍能看到当前公开摊位；不显示其个人距离，也不虚构位置。 |
| AC-02 | 用户提交摊主资料，审核尚未通过或被驳回 | 顾客端不可见，该用户不能开摊；驳回原因对本人可见。 |
| AC-03 | 审核通过的摊主确认有效收摊时间并定位成功 | 只产生一轮出摊；顾客列表、地图和详情显示当前营业位置及预计收摊时间。 |
| AC-04 | 截止时间无效、定位失败或中途取消 | 仍为休息中，不形成营业地址或出摊日；摊主看到原因并可重试。 |
| AC-05 | 摊主刷新位置成功，随后再刷新失败 | 顾客导航使用第一次刷新后的最新成功位置；失败不清空该位置，也不增加出摊天数。 |
| AC-06 | 本轮进入准备收摊阶段，顾客点击导航 | 顾客先看到预计收摊时刻与剩余时间，可决定是否继续导航。 |
| AC-07 | 摊主手动收摊，顾客持旧详情页再次点击导航 | 顾客看到已休息，不能获取旧营业坐标或继续按“正在营业”导航。 |
| AC-08 | 小程序关闭后到达预计收摊时间，自动任务发生重试 | 权威状态仍只收摊一次；新的读取和导航立即按已收摊处理，正常网络下已打开的前台页面最多 60 秒同步，工作台记录实际结束时间。 |
| AC-09 | 同一天多次开摊，或一次营业跨越零点 | 当天只计一个出摊日；跨零点不自动计次日，次日结束本轮并重新定位开摊后才计次日。 |
| AC-10 | 顾客在对应轮次营业中或实际结束后不足 30 分钟时提交现场状态反馈 | 满足 C-03 核验条件的反馈进入本人记录和人工复核；重复同类待处理反馈不重复生成，提交本身不自动处罚。 |
| AC-11 | 有权限管理员暂停正在营业的摊主公开，旧开摊请求稍后返回 | 本轮结束，资料和位置立即不公开；旧请求不能重新开摊。恢复公开后仍为休息中。 |
| AC-12 | 已审核摊主修改资料，随后审核被驳回 | 顾客端持续看到原已通过资料；被驳回内容不生效。 |
| AC-13 | 无管理权限账号通过旧页面或直接请求执行审核、暂停 | 操作被拒绝，摊主资料、状态和位置不改变。 |
| AC-14 | 本轮位置长时间未刷新，随后主动刷新失败 | 本轮尚未结束时保留最后成功位置和其真实更新时间，不虚构实时跟踪或自动收摊；到本轮结束时立即停止新读取和导航使用。 |
| AC-15 | 提交反馈时位置距事件有效营业位置恰为 300 米、定位距提交恰为 5 分钟，或分别超过边界 | 恰好达到距离与定位时间上限可通过对应核验；超过任一上限则说明原因并允许重新定位，不生成有效反馈。其他受理条件仍须同时满足。 |
| AC-16 | 同轮从 A 点刷新到 B 点，或收摊后同日重新开摊，顾客在受理窗口内反馈旧事实 | 按事件发生时的轮次、位置与状态核验，不把对象替换为新位置或新轮次，不对顾客返回旧坐标；历史异常不会自动结束后续轮次。 |
| AC-17 | 顾客离开详情后，从“我的 → 现场反馈”找回已查看或导航轮次 | 受理窗口内可继续反馈；到该轮结束后 30 分钟关闭其新反馈入口。跨零点按异常发生日合并同类待处理反馈，已提交记录仍可查询。 |
| AC-18 | 旧页面断网或无法取得最新状态，顾客再次点击导航 | 提示无法确认最新状态，不以缓存坐标新发起导航；恢复网络并复核后按当前状态处理。 |
| AC-19 | 摊主营业中本人确认停止公开，并请求清除不再需要的个人资料；之后本人尝试恢复公开 | 停止公开立即成立，本轮结束、资料和位置停止公开且不能再开摊，无需管理员受理；资料清除按可清除范围和期限处理并说明必要保留。本人恢复不解除治理暂停；基本资料已删除时先补齐并重新审核，恢复后不自动开摊或公开旧位置。 |
| AC-20 | 营业位置被成功刷新替换，或本轮收摊、暂停公开 | 被替换位置不再作为当前导航位置返回，收摊或暂停后不返回旧营业坐标；各版本按各自停止公开时刻计算受限保留期，期限届满且无有效延期时删除坐标或去标识化。 |

## 8. 试点观察与下一期进入条件

第一期记录审核通过后的开摊使用、有效出摊次数、顾客查看详情与发起导航、摊主再次使用、自动收摊准确性，以及“显示出摊中但现场不符”的反馈比例。数据只用于判断真实供给、状态可信度和顾客使用意愿；本文不预设未经试点验证的数值目标。

试点开始前，业务负责人记录观察起止日期、片区、参与摊主、主要营业时段和抽查安排；每个观察周期结束形成“进入下一期／继续观察／调整试点”的评审记录，注明样本不足、异常原因与负责跟进的人。观察周期的具体日期属于试点安排，不作为功能实现中的固定时长。

| 观察项 | 统一口径 |
| --- | --- |
| 开摊使用与成功 | 按确认收摊时间并开始定位的开摊尝试统计，网络重试合并；分别记录成功、定位或时间失败、主动取消。有效出摊次数指成功形成的营业轮次，不等同于第二期的“信用有效出摊日”。 |
| 摊主再次使用 | 在观察期至少成功开摊一次的摊主中，统计在另一个自然日再次成功开摊的人数及比例，并说明可观察天数；当天重复开摊不算跨日留存。 |
| 顾客查看与导航 | 分别统计详情查看和导航前复核通过后发起导航的人数、次数；发起导航不视为已经到达或成功找到摊主。 |
| 状态和位置准确性 | 通过人工现场抽查、试点回访核对同一时刻公开状态、位置与实际营业是否一致，记录核验成功、发现异常和无法确认的样本；没有收到反馈不能推定现场准确。 |
| 现场异常反馈 | 按营业轮次去重统计收到反馈、已核实异常和待处理的数量；已核实异常轮次数与观察期成功营业轮次数分别列明，跨周期复核保留原轮次归属，不把待处理或未核实一律算成准确。 |
| 自动收摊和人工纠错 | 抽查到期和本人停止公开后的新读取、导航是否立即失效，前台同步是否满足 R-01；记录反馈处理时长，以及本人资料清除的完成情况、必要保留说明与争议核查情况。 |

只有第一期的状态和位置准确性有现场核验依据、R-01 等质量要求已通过验收、管理人员能处理错误营业信息，才进入第二期的计划、请假与“今天想去”。样本不足时继续观察，不仅凭导航点击量或反馈数量少判定通过。

第二期开始前需为既有摊主明确展示新日历规则，新计划最早从次一自然日生效，不追溯产生第一期的未按计划出摊事件。2B 启用最近出摊位置前，须另告知位置用途、7 日公开期、停止公开入口及到期结果；第一期已经停止公开或仅供受限审计保留的位置不得因升级重新公开。只有告知后主动开摊或主动刷新新取得的位置版本才适用新公开规则，未重新定位的旧轮次仍按第一期规则收摊即停止公开。

## 9. 与完整需求的阶段性差异

1. 完整需求有三种公开状态且要求预计出摊日历不可为空；第一期只交付“出摊中、休息中”，不设置日历和请假，不执行计划日信用规则。
2. 完整需求允许休息中或请假中限期公开最近出摊位置；第一期一经收摊就停止向顾客公开营业坐标。
3. 完整需求包含关注、当日预约、微信订阅提醒、核销、信用和申诉等能力；第一期只交付实时找摊与简易现场状态反馈，以上能力后置。
4. 完整需求允许摊位图片、商品逐项新增和排序；第一期只采集基本文字资料并使用默认品类视觉，第二期再完善资料展示。

后续开发不得把第一期的简化当成完整需求已经实现。若本期范围发生变化，先更新本文及对应验收场景，再拆分实施任务。
