# 用户表与类型关联设计

> 状态：设计草案，表结构尚未实施

## 表命名与关联方式

表名统一采用 `cb_<模块名>_<表名>`：`cb` 是项目简称，后两部分使用小写字母和下划线，表名使用单数。例如：

- `cb_user_account`：`user` 模块的 `account` 表，保存用户共通信息。
- `cb_vendor_identity`：`vendor` 模块的 `identity` 表，保存摊主身份信息。

各表使用 `id` 作为自身主键。类型扩展表用 `account_id` 关联 `cb_user_account.id`；用户表不保存各类型表的反向 ID。

```text
cb_user_account.id
    ├── cb_vendor_identity.account_id
    └── 其他类型表.account_id（需要时新增）
```

## 用户表 `cb_user_account`

用户表是小程序登录后的统一账号记录，也保存各类型共用的基本资料。

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | `BIGINT UNSIGNED` | 主键，自增 | 用户内部 ID，供其他表关联。 |
| `wx_openid` | `VARCHAR(128)` | 必填，唯一 | 微信身份标识，用于登录时查找账号。 |
| `wx_unionid` | `VARCHAR(128)` | 可空，非空时唯一 | 取得 UnionID 后用于关联同一微信开放平台下的身份。 |
| `status` | `VARCHAR(16)` | 必填，默认 `ACTIVE` | 账号状态：`ACTIVE`、`LOCKED`、`DELETED`。 |
| `nickname` | `VARCHAR(128)` | 可空 | 用户昵称。 |
| `avatar_url` | `VARCHAR(1024)` | 可空 | 用户头像地址。 |
| `phone` | `VARCHAR(32)` | 可空 | 经可信微信手机号授权取得的号码。 |
| `created_at_ms` | `BIGINT UNSIGNED` | 必填 | 创建时间，毫秒时间戳。 |
| `updated_at_ms` | `BIGINT UNSIGNED` | 必填 | 更新时间，毫秒时间戳。 |

登录时根据可信的微信身份信息匹配 `wx_openid`，再读取账号状态；客户端传入的用户 ID 不作为登录凭据。用户是否拥有摊主等身份，以对应扩展表的记录为准。

## 摊主表 `cb_vendor_identity`

摊主表只保存摊主身份专属信息，通过 `account_id` 指向用户表。

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | `BIGINT UNSIGNED` | 主键，自增 | 摊主身份记录 ID。 |
| `account_id` | `BIGINT UNSIGNED` | 必填，建立索引 | 关联 `cb_user_account.id`。 |
| `vendor_code` | `VARCHAR(32)` | 必填，唯一 | 稳定的摊主编码。 |
| `lifecycle_status` | `VARCHAR(32)` | 必填 | 用于区分当前身份与历史记录；具体状态另行设计。 |

一个用户可以没有摊主记录，也可以同时关联其他类型。若保留摊主历史记录，同一用户可以对应多条摊主记录，但同时最多有一条未永久注销的记录，因此 `account_id` 不设置无条件唯一约束。其他类型是否允许多条记录，由各自的表设计决定。
