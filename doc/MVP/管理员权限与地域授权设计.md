# 管理员权限与地域授权设计

> 状态：设计草案，授权表和授权逻辑尚未实施

## 设计原则

- `cb_user_account` 负责登录和账号状态；摊主身份由 `cb_vendor_identity` 表示；管理身份与操作权限独立授予。同一账号可以同时是摊主和管理员，但摊主身份不带来管理权限。
- `SUPER_ADMIN` 拥有全国范围的全部管理权限，负责授予和撤销管理员角色及权限。`ADMIN` 只拥有被明确授予的“操作＋地域”组合；未授权默认拒绝。
- 权限按服务端操作定义，而不是按页面定义。权限代码由服务端维护，数据库中的目录用于展示和授权选择，不能通过管理界面任意新增权限代码。

## 1. 管理角色 `cb_user_role`

| 字段 | 类型 | 约束与含义 |
| --- | --- | --- |
| `id` | `BIGINT UNSIGNED` | 自增主键。 |
| `account_id` | `BIGINT UNSIGNED` | 必填，关联 `cb_user_account.id`。 |
| `role_code` | `VARCHAR(16)` | 必填：`ADMIN` 或 `SUPER_ADMIN`。 |
| `status` | `VARCHAR(16)` | 必填：`ACTIVE` 或 `REVOKED`。 |
| `granted_by_account_id` | `BIGINT UNSIGNED` | 授权人账号 ID；首次引导创建超级管理员时可为空。 |
| `granted_at_ms` / `revoked_at_ms` | `BIGINT UNSIGNED` | 授予时间必填，撤销时间可空。 |

唯一键为 `(account_id, role_code)`；另建 `(role_code, status)` 索引。再次授予已撤销的角色时更新原记录，历次操作保存在授权事件表中。

## 2. 权限目录 `cb_admin_permission`

| 字段 | 类型 | 约束与含义 |
| --- | --- | --- |
| `permission_code` | `VARCHAR(64)` | 主键，稳定的操作代码。 |
| `permission_name` | `VARCHAR(128)` | 管理端展示名称。 |
| `permission_group` | `VARCHAR(32)` | 权限分组。 |
| `grantable_to_admin` | `TINYINT(1)` | 是否允许授予普通管理员。 |

权限目录由受控初始化数据维护，与服务端权限检查代码保持一致。候选操作包括摊主资料审核、摊位停用、摊位恢复、投诉处理、违规认定和内容处置；具体代码与操作边界在实现各管理功能时确定。管理员授权与系统配置等操作仅由 `SUPER_ADMIN` 执行，不向普通管理员开放。

## 3. 管理员授权 `cb_admin_permission_grant`

每行代表一个 `ADMIN` 对一项操作在一个地域范围内的授权。

| 字段 | 类型 | 约束与含义 |
| --- | --- | --- |
| `id` | `BIGINT UNSIGNED` | 自增主键。 |
| `account_id` | `BIGINT UNSIGNED` | 必填，被授权管理员的账号 ID。 |
| `permission_code` | `VARCHAR(64)` | 必填，关联权限目录中的代码。 |
| `scope_type` | `VARCHAR(16)` | 必填：`NATIONAL`、`CITY` 或 `REGION`。 |
| `scope_key` | `VARCHAR(64)` | 必填，按下表解释。 |
| `status` | `VARCHAR(16)` | 必填：`ACTIVE` 或 `REVOKED`。 |
| `granted_by_account_id` / `granted_at_ms` | `BIGINT UNSIGNED` | 最近一次授予的操作人及时间。 |
| `revoked_by_account_id` / `revoked_at_ms` | `BIGINT UNSIGNED` | 最近一次撤销的操作人及时间，可空。 |

唯一键为 `(account_id, permission_code, scope_type, scope_key)`；建立 `(account_id, status, permission_code)` 索引。撤销后再次授予同一组合时更新原记录，完整变更历史由事件表保存。`SUPER_ADMIN` 不需要在本表逐项存储通配授权。

| `scope_type` | `scope_key` | 生效范围 |
| --- | --- | --- |
| `NATIONAL` | `*` | 全国。 |
| `CITY` | 稳定的城市代码 | 该城市及其现有、未来新增的经营区域。 |
| `REGION` | `cb_location_region.id` 的十进制字符串 | 指定经营区域。 |

区域授权使用不可随名称修改而变化的 `id`。现有区域记录的 `region_code` 可以被修改，不适合作为长期授权键。城市代码需要可信、统一的代码来源；现有 `cb_location_region.city_code` 是区域的城市归属字段，不能单独充当完整的城市字典。

## 4. 授权事件 `cb_admin_authorization_event`

| 字段 | 类型 | 约束与含义 |
| --- | --- | --- |
| `id` | `BIGINT UNSIGNED` | 自增主键。 |
| `actor_account_id` | `BIGINT UNSIGNED` | 操作人账号 ID；首次引导创建超级管理员时可为空。 |
| `target_account_id` | `BIGINT UNSIGNED` | 被授权或撤销授权的账号 ID。 |
| `event_type` | `VARCHAR(32)` | `ROLE_GRANT`、`ROLE_REVOKE`、`PERMISSION_GRANT` 或 `PERMISSION_REVOKE`。 |
| `role_code` | `VARCHAR(16)` | 角色事件填写，其他事件可空。 |
| `permission_code` | `VARCHAR(64)` | 权限事件填写，其他事件可空。 |
| `scope_type` / `scope_key` | `VARCHAR(16)` / `VARCHAR(64)` | 权限事件填写，角色事件可空。 |
| `reason` | `VARCHAR(500)` | 授权或撤销原因。 |
| `created_at_ms` | `BIGINT UNSIGNED` | 事件发生时间。 |

事件只追加、不改写；建立 `(target_account_id, created_at_ms)` 和 `(actor_account_id, created_at_ms)` 索引。当前权限只由角色表和授权表的有效记录决定，不从事件日志回放。

## 授权判定与数据边界

1. 服务端先用可信微信身份确定账号，并检查账号状态。有效的 `SUPER_ADMIN` 角色直接通过管理权限检查。
2. 普通管理员必须有有效的 `ADMIN` 角色、权限目录中允许授予的操作，以及匹配操作对象地域的有效授权。全国、城市、区域授权取并集；撤销一条授权不影响其他仍有效的授权。
3. 操作对象的城市和区域由服务端从可信数据读取，不接受客户端自报。投诉和违规案件应保存事发时的城市及区域归属，以免摊位迁移改变历史案件的管理范围。没有可信地域归属的对象不能通过地域授权放行。
4. 撤销 `ADMIN` 角色时，在同一事务中撤销其全部有效操作授权，并写入授权事件，避免以后重新授予角色时旧授权自动恢复。角色、权限与地域记录在写入授权前也须校验有效性。

本项目现有迁移不建物理外键；关联字段需建立索引，并在服务端事务中校验引用关系。当前管理鉴权仍使用运营人员白名单，本设计尚未替换现有实现。
