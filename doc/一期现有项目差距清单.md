## 5. 数据、接口及工程基础的具体缺口

### 5.1 数据和迁移

当前源码迁移只定义 cb_location_region、cb_vendor_locations 及 last_located_at_ms 补列。账号、摊主身份、资料版本／审核申请、营业轮次、出摊日、反馈事实／处理、独立公开限制、清除请求和相关审计未见已实施迁移。这里描述的是源码，实际数据库表清单仍待连接核验。

位置记录已有发布／停止等字段，但成功替换旧位置的 UPDATE 仅设置状态与 updated_at_ms，未写 stopped_at_ms，也没有营业轮次引用。不能据此完成“每个版本自身停止公开时间”和具体营业轮次反馈核验。

迁移运行器中有 ensureMetadataTable，但当前 runMigrations 未调用它；现有迁移也未创建 cb_schema_migrations，而执行后会向该表写记录。存在空库迁移的元数据表初始化风险，尚未以真实空库复现，不作为已确认运行故障。

证据：[位置迁移](../backend/src/database/migrations/0002_create_cb_vendor_locations.js)、[定位补列](../backend/src/database/migrations/0003_add_last_located_at_ms.js)、[迁移运行器](../backend/src/database/migration-runner.js)。

### 5.2 客户端声明与后端服务不是一回事

account.js 声明 /api/v2/me，status.js 声明 /api/v2/vendor/sessions/open、close、location/refresh，feedback.js 声明 /api/v2/field-feedback；当前后端装配仅有位置和区域路由。不能将这些 API 包装的存在标为对应业务已经完成，也不能先假定其参数就是一期最终接口约定。

withIdempotency 支持传入已有幂等标识，但未传时每次调用生成新标识。仅有请求头不能证明网络重试复用同一操作，更不能证明数据库去重和并发正确；目前未找到这些营业写接口的服务端实现。

证据：[请求工具](../miniprogram/utils/request.js)、[幂等包装](../miniprogram/api/core-v2.js)、[账号包装](../miniprogram/api/account.js)、[营业包装](../miniprogram/api/status.js)、[反馈包装](../miniprogram/api/feedback.js)。

### 5.3 调度和运行

job-token.js 提供令牌校验中间件，但当前路由未挂载一期到期收摊或资料清理任务；中间件存在不等于任务可运行。现有 location:expire:once 处理最近位置公开期，不能替代到时收摊。

backend/package.json 的 admin:seed-super、jobs:core:once、calendar:import、outbox:once 指向当前目录清单中不存在的脚本。Docker 仅复制 src，部署时脚本可用性也不能按本地目录推定。尚未验证真实云配置、管理员配置、调度触发、容器构建和回退。

证据：[后端脚本声明](../backend/package.json)、[作业令牌](../backend/src/middlewares/job-token.js)、[现有到期脚本](../backend/scripts/run-location-expiry-once.js)、[Dockerfile](../backend/Dockerfile)。
